# Vision: WEB-Приложение онлайн реализации и бронирования билетов

> Документ декомпозирует ТЗ заказчика в трассируемые требования.
> Каждое требование имеет ID и ссылку на спек шага, где оно реализуется.

## 1. Видение

Система управления продажей и бронированием билетов на мероприятия (музей /
мероприятия заказчика). Backend — REST API на Python 3.12 + PostgreSQL 16
(Docker). Frontend разрабатывается отдельно, взаимодействие по HTTP/JSON.

## 2. Подсистемы → модули API

| Подсистема ТЗ | Модуль backend | Шаг |
|---|---|---|
| Взаимодействия с клиентом | `routers/public`, `routers/client` | 4, 5 |
| Пользователя системы | `routers/admin` | 6 |
| Управления продажами | `services/*` (платежи, рассылка, аудит) | 7, 8 |

## 3. Требования (трассировка ТЗ)

### 3.1 Клиентская подсистема

- **C-1** Афиша / выбор мероприятий: список активных мероприятий с мини-баннером. → Спек 04
- **C-2** Карточка мероприятия: описание, дата, место, длительность,
  возрастное ограничение, крупный баннер, опционально кол-во свободных мест. → Спек 04
- **C-3** Справочная информация о сервисе (читается из БД). → Спек 04
- **C-4** Регистрация / авторизация клиента (email + пароль). → Спек 03
- **C-5** Личный кабинет: профиль, история заказов, скидки/особые условия. → Спек 05
- **C-6** Бронирование и покупка билетов; покупка доступна только авторизованному. → Спек 05
- **C-7** Отмена билетов из личного кабинета. → Спек 05

### 3.2 Подсистема пользователя системы

- **S-1** Авторизация персонала; RBAC: права определяют доступный функционал;
  администратор имеет полные права. → Спек 03
- **S-2** Управление мероприятиями: создание, баннеры, цена, даты, возрастное
  ограничение, описание, продолжительность, место, показ остатка, билеты,
  клонирование, перенос/отмена, приостановка продаж. → Спек 06
- **S-3** Управление клиентами и пользователями системы. → Спек 06
- **S-4** Скидки/тарифы/акции; скидки двух уровней: глобальные (все клиенты)
  и индивидуальные. → Спек 06
- **S-5** Онлайн-кассир: продажа безналом/по счёту, отмена заказа, возврат денег. → Спек 08
- **S-6** Отчёты: статистические и бухгалтерские. → Спек 09
- **S-7** Информирование о системе: ошибки, состояние, журнал событий. → Спек 07
- **S-8** Настройки системы: пользователи, параметры обмена. → Спек 06

### 3.3 Подсистема управления продажами (сквозные требования)

- **D-1** Данные не удаляются: soft-delete + версионирование изменяемых записей. → Спек 02
- **D-2** Аудит-лог всех действий пользователей системы; годовые партиции. → Спек 07
- **D-3** Логирование клиентов (действия клиентов фиксируются). → Спек 07
- **D-4** Lockout: 3 неудачных входа подряд → блокировка на 30 минут. → Спек 03
- **D-5** Одна активная сессия на учётную запись (вход с другого устройства
  запрещён до выхода/истечения). → Спек 03
- **D-6** Белые/чёрные IP-списки, ограничение по стране — конфигурируемо. → Спек 10 (post-MVP)
- **D-7** Платёжный модуль uniPayment: оплата и возврат; в MVP — mock/sandbox. → Спек 08
- **D-8** Рассылка писем: заказ, электронный билет, отмена, возврат, подтверждение оплаты. → Спек 08
- **D-9** Модуль обмена данными с системами заказчика — контрактный интерфейс. → post-MVP
- **D-10** Ежегодная ротация экземпляров БД мероприятий; незакрытые мероприятия переносятся. → post-MVP (архивация)

## 4. Нефункциональные требования

| ID | Требование | Решение |
|---|---|---|
| NF-1 | Масштабируемость | Stateless API, горизонтальное масштабирование; конкурентная бронь через `FOR UPDATE SKIP LOCKED` |
| NF-2 | Безопасность | Argon2id-хеши паролей, JWT access+refresh, RBAC, rate limiting, валидация Pydantic |
| NF-3 | Производительность | Индексы под афишу/поиск; пул соединений; кэширование афиши (ETag) |
| NF-4 | Надёжность платежей | Идемпотентные webhooks, статусная машина заказа |
| NF-5 | Аудируемость | Append-only audit log, никакие записи не физически не удаляются |
| NF-6 | Тестируемость | pytest, ≥80% покрытия ядра, тесты конкурентности бронирования |

## 5. Границы MVP (шаги 1–9)

Включено: C-1…C-7, S-1…S-7, D-1…D-5, D-7(mock), D-8, NF-*.
Отложено: D-6, D-9, D-10, конструктор шаблонов документов, абонементы,
пригласительные, интеграция с сайтом museum.goznak.ru.
